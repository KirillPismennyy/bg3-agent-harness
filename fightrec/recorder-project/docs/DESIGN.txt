2. Verified source defects and capability decisions
The helper osi returns only its first successful return value (local ok,r=pcall); therefore assigning x,y,z=osi(Osi.GetPosition,...) loses Y/Z in this source. Claude must preserve multiple returns or use an independently verified position API; absence is explicitly unavailable, never zeros. This explains the observed pattern but does not authenticate historical code.
Writer serializes every add, retains every line, concatenates and rewrites full history every >=2000ms plus forced flushes. It clears dirty before SaveFile and treats pcall success as write success; upstream SaveFile returns bool. Both thrown errors and false return must retain retryable data and mark integrity. Client has no observed explicit terminal flush; server flushes at start/end. PREP_KEEP=300 and PREP_MS=10min silently prune prehistory today; new schema must report window and evicted counts. FR.dump truncates after serialization, so DUMP_MAX does not bound serialization allocation. Client dump node/depth limits truncate data and must be exported as completeness flags. BeforeDealDamage lacks top-level Caster/Target upstream, so current filter can record unattributed global events. Do not label those party scoped without resolution.
Current upstream IO.inl registers AppendFile(path,contents), returns bool, writes with append=true. Baseline comment claiming no append is obsolete for upstream, but loaded runtime remains unknown (cache has v29/31/32/33). At load emit actual SE identity if available plus source-linked capability table. Use append only after capability and semantics verification on the running version in a later authorized live test. No speculative invocation of component subscription APIs. Missing optional hooks must not prevent core capture; hook absence and registration errors are durable records.
Upstream DealtDamage.Result exists. Copy its needed fields inside callback, guard unavailable fields and record errors. ExecuteFunctor/AfterExecuteFunctor carry Params and post Hit upstream; they are optional experimental diagnostics until miss/save coverage and callback cost are demonstrated. Do not globally dump every functor by default. Initiative observation may expose an order/value via validated components; no initiative die or tie logic claim without evidence. Observed enemy actions do not expose AI reasoning.

3. Capture contract (version 2; legacy remains importable)
Required envelope: schema_version, recorder_version, source_sha256 (build-supplied exact artifact hash or explicitly unknown), session_id, context(server/client), stream_id, combat_id if known, monotonically increasing seq, callback-entry monotonic time plus clock unit/domain, kind, phase, data, completeness/errors. Never assert wall clock synchrony across contexts. Unique session identity must survive same-second reloads without filename collision; stream counters distinguish reset/client/server. No network dependency merely to correlate clocks.
Meta: game raw version, SE raw version/unavailable, hook/API capability and registration results, configuration including thresholds, source identity, start mode (normal/mid-fight), settings evidence provenance and explicit unknowns. External save hashes belong to an intake manifest, not inferred runtime settings. No silent claim of vanilla equivalence.
Actor identity: UUID where verified; entity kind, template if available, entity lifetime/session; unknown and destroyed are distinct. Do not infer identity from list order. Resource maps keyed by resource UUID and level; HP/max/temp, statuses with instance/source/duration fields when available, position object x/y/z plus validity, coordinate domain and sample seq/time. Preserve unknown fields and original event names for compatibility. Omitted delta field means unchanged; explicit unavailable/tombstone means different from unchanged. Distinguish absent status, unknown status and unobserved status changes.
Full metadata/gear snapshot only at start/end and deliberate diagnostic checkpoints. Small dynamic checkpoints at turn boundaries and action observations: relevant participants immediately, dirty participants after event bursts, periodic full dynamic reconciliation to catch unhooked changes. Label each snapshot as event-adjacent or deferred; deferred is not the precise action boundary. Record checkpoint begin/end seq and times, per-actor sample time; never call a sequential scan atomic. Snapshot recursion/nesting is guarded and errors retained.
Action observations have actor, targets/position, spell/action/item, phase, turn/round identifiers, native StoryActionId/Originator when present and copied safely. A local observation ID is not a guaranteed native action ID. Retain many-to-many correlation candidates and confidence; do not combine UsingSpellOnTarget, CastedSpell, damage groups or multi-target/reaction events solely by timestamp. Preserve callback-entry order with placeholders/reservations so nested callbacks cannot invert seq. Status/damage may occur before/after CastedSpell; producer order is observation order, not a universal causality claim.
Dice: copy individual die values, sizes, modifiers, advantage/disadvantage, rerolls, check/DC/AC and outcome flags only where actually exposed; field provenance and absent reasons required. Damage Before/Deal/Dealt phases remain separate; Result raw validated fields are observations. RollResult is not a full numerical stream. No complete RNG capture or seed equivalence guarantee.
Movement optional, default off until cost verified: ~4Hz, Euclidean XYZ displacement >0.25m from last EMITTED sample, cumulative small movements eventually cross threshold. Always take boundary positions irrespective of threshold. Mark sample time/delta and suppressed count; no exact path, velocity, teleport detection or intermediate reach/LOS proof. A move out-and-back within 250ms can be invisible. Finite speed v alone bounds inter-sample distance by v*dt, not reconstruction of path/LOS; teleports void that bound. Event-sourced movement is preferable only if a tested API actually provides it.
UI combat log remains auxiliary. Its fingerprint is not globally unique, entries can mutate and lists can rebuild. Export route_loss/resync/ambiguous_duplicate/backlog/truncation and observed collection generations. Never deduplicate server events by translated text. Client must allow at most one queued/running deferred UI poll; schedule the next poll after completion. No unsafe direct UI access fallback if UI.Defer is unavailable: mark UI capture unsupported while server continues.

4. Storage, bounded work, and failure semantics
Prefer numbered independently readable parts in separate session/context/stream namespaces. Choose append-to-active-part only after verified support; SaveFile fallback rewrites ONLY active part. Cap C is a target byte size, not permission to truncate one large event. Single oversized records become dedicated parts with explicit size diagnostics; per-record copy limits flag missing fields. Never retain live userdata for deferred work. Cheap safe scalar/owned payload copying occurs synchronously; encode/write may be deferred only for owned immutable data, with measured callback cost.
Sealed parts immutable. Each has metadata header (stream/part/first seq), records and trailer (last seq/count/byte checksum if validated implementation available). Active partial tails tolerated only as incomplete evidence. Manifest stores completed part index/ranges/checksums and completion state. Avoid rewriting an ever-growing manifest every part: use bounded journal/index segments plus a small head/checkpoint or build final manifest once at normal completion. Readers can reconstruct from deterministic numbered parts without trusting a missing/stale manifest. No rename/atomic-save/fsync guarantee without runtime evidence. Explicitly identify crash exposure of active rewritable part, append tail and buffered queue.
Successful acknowledgement requires API pcall success AND affirmative write return (respect verified version signature). On failure retain immutable retry payload and exact path/range. Append retry after ambiguous partial success risks duplicates: do NOT blindly append same bytes; recover by validating/re-reading committed sequence/tail where supported, otherwise mark stream integrity failed and rotate to a new recovery part with duplicate uncertainty. Rewritten active-part retry is idempotent for owned payload but still not atomic. Readers reject conflicting duplicate seq payloads, report identical duplicates, missing parts, discontinuities and mismatched trailers.
Queue finite: configurable byte and record limits, high/low-water marks; report observed occupancy and oldest age. If production exceeds service capacity, reduce optional polling/diagnostic capture first and emit degradation reason and interval. Never discard required observations silently. If required queue cannot drain, transition capture to explicitly FAILED/INCOMPLETE, preserve admitted records, console warning and persistent gap/counter once writes recover. Reserved loss-counter capacity and out-of-band warning still needed when disk is unavailable. No system can guarantee lossless, bounded memory and bounded callback time under arbitrary producer overload or permanent write failure. Avoid large synchronous emergency flush as an unmeasured hitch solution.
Normal combat end enqueues final snapshot/end; writer stays alive until drain is acknowledged, then seals part and marks complete. Client session shutdown/reload/reset uses only validated lifecycle hooks and best effort final flush; abrupt process termination cannot guarantee it. Mid-fight load/unload/disconnect/multiple combats and overlapping party combats must produce explicit scope transitions or unsupported/incomplete records, never silently overwrite a single active fight. Partial/final flush ordering includes records arriving during finalization.

5. Cost analysis (assumptions are explicit; no benchmark result claimed)
N combatants, E admitted event records, P polls, A action checkpoints, S average small dynamic actor bytes/work units, H full actor snapshot cost, B final encoded bytes, R average encoded event size, F flushes, b_j accumulated bytes at flush j, C target part bytes, L maximum record bytes, Q queued owned bytes. Reflection cost depends on reachable members/depth, not just output size. Engine queries and filesystem calls are variable-latency; proportional models are approximations to measure.
Current encode total approximately proportional to B plus reflection/queries; add worst case includes unbounded per-record reflection/serialization. Tick without flush O(1). Concats/write allocation and I/O sum_j b_j; peak retained payload Theta(B), transient concat Theta(B), plus engine reflection and Lua overhead. If equal-sized records and every fixed k records a flush, F~E/k and sum b_j=R*k*F(F+1)/2=Theta(R*E^2/k) for fixed k,R; amortized bytes per event Theta(R*E/k), largest flush Theta(B). If only a fixed number F of flushes, sum b_j=O(F*B), not automatically quadratic. Forced writes change F. Callback time = query+copy+encode for event callback, and concat+write when it invokes flush; worst callback is max of these plus full snapshot/UI scans where applicable, not average total/E. Current memory grows with client session even outside combat.
Fallback active-part rewrites: general bound O(B + F*(C+L)), with F counting scheduled/forced active rewrites and excluding one-time seals. For equal records of R bytes, m=C/R records per filled part (assume integral), k records per scheduled flush, and 1 <= k <= m with k dividing m, active-prefix bytes per part are R*k*(m/k)*(m/k+1)/2; across E/m filled parts this is Theta(E*C/k + E*R), plus Theta(B) seal writes. If k > m, seals dominate and the interior-prefix tight expression does not apply. Small/forced flushes have their actual prefix-sum cost. More simply compare measured sum active prefixes to sum history prefixes. With fixed C,k,R,L and proportional data growth B=Theta(E), this is Theta(E), and is little-o(E^2) as E->infinity under those assumptions only. If C grows with B, that advantage may disappear. Peak active storage O(C+L+Q), plus actor caches O(N*S); indexes must also be segmented/streamed to avoid O(B) memory. Sync fallback flush still costs proportional to C+L plus unpredictable filesystem latency; cap does not guarantee frame budget.
Append: encoding/copy Theta(B) under bounded shapes; appended payload Theta(B), plus headers/trailers/metadata and per-call overhead Theta(F). Joining each batch costs batch bytes. Peak O(batch+L+Q+N*S), disk can remain O(B). Append is not zero-copy nor async by assumption. A single expensive record can still hitch.
Per-poll full dynamic scan Theta(P*N*S), per-action full scan Theta(A*N*S), full metadata Theta(N*H) each checkpoint. Dirty approach Theta(E*c_mark + D*S + K*N*S), with D actor refreshes, K reconciliations; worst D can be Theta(A*N), so no universal strict improvement. Unhooked changes require reconciliation; conservative invalidation may mark all N. Movement polling alone costs Theta(P*N) position queries even when emits none; delta thresholds reduce bytes, not query count. Membership caches must invalidate on joins/leaves, death and scope transitions, not just timer expiry.
Client: tree search visits V nodes/edges with stored route copying proportional to sum route depths, up to SEARCH_BUDGET=40000 visits (not a frame-time bound). Resync can scan M entries; each dump bounded by node/depth budgets but engine property calls remain expensive. At 2 entries/0.5s, nominal maximum drain is 4 entries/s BEFORE processing delays. For arrival lambda and measured service mu, backlog growth ~max(0,lambda-mu)*T. Stable average requires lambda<mu plus burst capacity; 479 entries across a 516-second fight would not establish peak stability (client log covers a broader session). Poll scheduling must use completion, not stack deferred callbacks. Compare callback p50/p95/p99/max and frame tails, not just throughput.

6. Failure/coverage matrix
Condition | required behavior | limit
Missing XYZ/component/hook | unavailable+capability record | no inferred zeros/full coverage
Miss/successful save/no damage | test optional functor hooks, preserve absence | damage hooks alone cannot cover
Multi-hit/AOE/reaction/nesting | native IDs+phase+seq+candidates | no timestamp-only grouping
Status/resource unhooked change | periodic dynamic reconciliation | intermediate timing remains unknown
Poll threshold/out-and-back | sample provenance+boundary sample | no continuous movement/LOS guarantee
UI route lost/rebuild/mutable row | generation/resync/gap flags | not authoritative numerical roll stream
Disk false/throw/partial append | retained retry/recovery+integrity failure | no durability/atomicity guarantee
Queue saturation | degrade optional work then explicit failure | finite buffer cannot guarantee losslessness
Reload/crash/mid-fight attach | unique stream/incomplete finality | final queued records may be lost
Prep/reflect truncation | window/eviction/cut flags | completeness qualified
Multiple combats/unknown participants | explicit scope/unsupported boundary | eight actors not total engine population proof
Stealth/native AI/RNG | explicit unsupported boundary | no full fight/Act 1 parity claim

9. Mandatory review resolutions (v1.1; supersede ambiguity above)
DR-01 generation ownership: v2 owns a separate versioned runtime namespace and immutable generation/artifact identity. On first load inspect presence of baseline FightRec registrations/state; if old unowned subscriptions cannot be detached with verified unsubscribe handles/APIs, refuse v2 activation and report fresh supported Lua lifecycle required. Do not modify baseline FR.registered or relabel old callbacks/state. Within v2 same-version reexecution is idempotent and retains same generation/queue; incompatible artifact/config generation replacement is refused until old generation is acknowledged drained and subscriptions safely retired, otherwise require lifecycle reset. Every callback checks its generation active state. Lifecycle reset cannot promise preservation of unflushed memory; mark abrupt prior streams incomplete when read. Tests include same-v2 execution twice, baseline-to-v2 replacement refusal, pending queue, stale callback, source hash identity and no duplicate registration. No production hot-unsubscribe claim without verified API.
DR-02 terminal reservations: admission capacity is checked before allocating a sequence; rejected admission increments bounded loss accounting with observation time and explicit capture failure. Every admitted seq terminates exactly once as owned event OR minimal reserved-capacity error/loss record at that SAME seq. Protected cleanup covers copy/snapshot/encode exceptions before/after nested callbacks. Drain only contiguous terminal prefix; reservations count toward queue record/byte capacity and age, and finalization cannot report complete with any reservation pending. If even minimal terminal encoding/storage fails, latch stream failed with bounded emergency counters and out-of-band warning; no indefinite wait or pretend completion. Fault injection verifies all these branches and accounting identities. Nested work must respect admission capacity rather than reserve unbounded placeholders.
DR-03 prep identity: assign session/context observation IDs and original callback times when events are first observed, including outside combat. Combat storage seq is distinct from observation ID and may reference earlier observations. Importer does not equate storage order of prep copies with native callback order. Prep copies preserve original observation ID/time and mark replayed-prehistory=true; per-combat storage seq remains contiguous. Eviction reports interval/count/reason, never invents missing observation identities. Test two combats, prep copying, eviction and reset identities.
DR-04 corrected the active-prefix formula in section 5 with general bound and restricted tight example. No little-o statement without fixed cap/shape/cadence and growing E.
DR-05 cached v33 source identity pins IO.inl to af85fd2bd2be28646539060d45df487f4d3314b9. Main-branch ServerEvents.h and FunctorEvents.inl remain exploratory references only; implementation must pin their inspected commit/API declarations before enabling production fields/hooks.
