What each pin establishes (declaration level) and how the recorder uses it
- IO.inl: SaveFile(path, contents) -> bool; AppendFile(path, contents) -> bool (append=true); LoadFile(path) ->
  optional string; both use the user-profile root. Recorder: an acknowledgement requires pcall success AND a
  return of exactly true; nil/false/throw are failures. AppendFile is used only with WRITE_MODE="append",
  APPEND_SEMANTICS_VERIFIED=true and a passing SaveFile/AppendFile/LoadFile self-test at load.
- ServerEvents.h: DealDamageEvent{Functor, Caster, Target, Position, IsFromItem, SpellId, StoryActionId,
  Originator, Hit, Attack(legacy DamageSums), HitWith, Caster2, SpellId2}; DealtDamageEvent adds Result
  (HitResult*); BeforeDealDamageEvent has ONLY Hit and Attack; ExecuteFunctorEvent{Functor, Params};
  AfterExecuteFunctorEvent{Functor, Params, Hit}. Recorder copies StoryActionId/Originator (DealDamage,
  DealtDamage), Result (DealtDamage), and attributes BeforeDealDamage via Hit.Inflicter or "unattributed".
- FunctorEvents.inl: DealtDamage's Result is the HitResult produced by the call (post), BeforeDealDamage fires
  before the stats system applies it. Functor pre/post events exist; they do NOT establish miss/save coverage.
- Hit.h: HitResult{Hit: HitDesc, Attack: AttackDesc, Results: HashMap<FunctorId,int32>, NumConditionRolls};
  HitDesc scalar fields (TotalDamageDone, DeathType, DamageType, CauseType, ArmorAbsorption, LifeSteal,
  EffectFlags, Inflicter, StoryActionId, HitWith, AttackRollAbility, SaveAbility, SpellAttackType,
  ConditionRolls, SpellCastGuid, SpellId, StatusId, SpellSchool, AttackFlags, SpellLevel, SpellPowerLevel,
  TotalHealDone, OriginalDamageValue, ...); ConditionRoll{RollType, Roll(variant), Difficulty, RollUuid,
  SwappedSourceAndTarget, Ability, Skill}; AttackDesc{TotalDamageDone, TotalHealDone, DamageList}.
  Recorder: copyResult() reads exactly these names, each guarded; unreadable ones go to result.missing.
  Individual die values inside ConditionRoll.Roll (StatsRoll/variant) are NOT copied: variant access is not
  pinned at the Lua binding level; the bounded legacy `hit` reflection may still contain them.
- Components/Data.h HealthComponent{Hp, MaxHp, TemporaryHp, MaxTemporaryHp, ...}; Status.h
